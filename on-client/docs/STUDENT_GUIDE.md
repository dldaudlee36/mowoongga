# 모웅가(mowoongga) 학생 설명서

이 문서는 학생 코드의 역할, 새 빈 폴더에서의 실행 절차, 기록된 로컬 관찰과 아직 확인하지 못한 연결을 구분해 설명합니다. 실행 결과는 `docs/NEW_ENVIRONMENT_RUN_LOG.md`에 남아 있던 기록을 정리한 것입니다. 이번 문서 편집 중에는 앱이나 브라우저를 다시 실행하지 않았습니다.

## 1. 새 빈 폴더에서 설치·실행

아래 절차는 PowerShell에서 `$env:TEMP` 아래에 새 임시 폴더를 만들고 공개 저장소를 복제하는 예입니다. 이미 `mowoongga-clean` 폴더가 있으면 다른 새 이름을 사용하세요. 사용자 이름이 포함된 컴퓨터별 절대 경로는 문서에 고정하지 않습니다.

```powershell
Set-Location $env:TEMP
New-Item -ItemType Directory -Name mowoongga-clean
cd mowoongga-clean

git clone https://github.com/dldaudlee36/Fightvac.git .
cd on-client
npm run check
```

프로젝트 README는 외부 npm 의존성이 없다고 안내합니다. 따라서 위 절차에는 `npm install`을 넣지 않았습니다. 기록에는 새 임시 폴더에서 `npm run check`가 정상 종료했다고 되어 있지만, 이 문서를 수정하며 재실행해 확인한 결과는 아닙니다.

앱 폴더(`on-client`)에서 아래 중 하나를 실행합니다.

- **예제 자료 화면:**
  ```powershell
  npm run demo
  ```
  브라우저에서 `http://127.0.0.1:5189`을 엽니다. 이 화면은 **예제 자료**이지 SDP/XDR 또는 AI 실서버 연결 증거가 아닙니다. 종료는 실행 중인 PowerShell에서 `Ctrl+C`입니다.
- **기본 실행:**
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
  ```
  브라우저에서 `http://127.0.0.1:5189`을 엽니다. 설정 없는 기본 실행은 실제 외부 시스템 연결을 뜻하지 않습니다. 종료는 실행 창에서 `Ctrl+C`입니다.

명령은 `on-client` 폴더에서 실행합니다. 데모와 기본 실행을 각각 확인하려면 한 서버를 `Ctrl+C`로 종료한 다음 다른 모드를 시작합니다. 버전 차이는 7절을 참조하세요.

## 3. 학생 렌더링 함수

아래는 `on-client/student/extension.mjs` 함수의 화면 역할입니다. 함수가 구현되어 있다는 것과 실제 원천 서버에 연결됐다는 것은 별개입니다.

| 함수 | 화면에 표시하는 내용 |
|---|---|
| `renderIdentity` | 사용자, 기기·세션 상태와 로딩·실패·동작 모드를 표시합니다. |
| `renderDecision` | 업무 앱 접속 판정·이유·시각을 표시하고 요청 실패와 `deny`를 구분합니다. 알 수 없는 판정을 허용으로 취급하지 않습니다. |
| `renderEvents` | 보안 기록 목록과 필터를 제공하고, 상세에 근거·규칙·상태 및 미지원 조치를 표시합니다. 실제 조치는 실행하지 않습니다. |
| `renderStatus` | 기기·세션·알림·제한된 진단 정보를 표시하고, 사용자가 누를 때 도움정보 복사를 시도합니다. |
| `renderAiConnection` | AI 연결 점검 상태와 오류 안내를 표시하며, 모델 목록 점검과 사건 설명 성공을 구분합니다. |
| `renderExplanation` | 선택 사건에 대한 참고용 설명·근거·규칙·상태·제안을 표시하고 근거 불일치를 성공으로 취급하지 않습니다. |
| `renderAction` | 조치 상태를 원래 코드와 함께 표시합니다. 효과 관측이 있을 때만 성공으로 표현하며 렌더러 자체에는 실행 버튼이 없습니다. |
| `renderVulnerabilities` | 전체·패키지별 취약점 조회 상태, lock 파일·버전·취약점 정보를 표시합니다. 실패나 확인 불가를 취약점 없음으로 바꾸지 않습니다. |

## 4. 실패·확인 불가 화면에서 살펴볼 점

| 화면 문구·상태 | 뜻과 확인할 내용 |
|---|---|
| `연결 실패: ...` | 사용자 정보 조회 실패입니다. 앱 서버와 표시된 오류를 확인하고 사용자 정보를 정상으로 간주하지 않습니다. |
| `요청 실패: ...` 및 deny가 아니라는 안내 | 접속 판정 요청 실패입니다. 오류를 서버의 `deny` 판정으로 기록하지 않습니다. |
| `확인 불가 (unknown) — 허용되지 않음 / 판정 불명` | 판정값을 모릅니다. 원천 응답을 확인하고 허용으로 추정하지 않습니다. |
| `기록을 불러오지 못했습니다: ...` | 기록 조회 실패이며 빈 목록이 아닙니다. 오류·응답을 확인합니다. |
| `선택한 조건에 맞는 기록이 없습니다` | 필터 조건에 맞는 기록이 없습니다. 필터를 확인하거나 전체 조건으로 바꿉니다. |
| `기기 정보를 불러오지 못했습니다: ...` / `세션 정보를 불러오지 못했습니다: ...` | 기기·세션 조회 실패입니다. 오류와 시간 초과 여부를 확인하고 위쪽 다시 불러오기 버튼을 직접 누릅니다. 자동 재요청은 하지 않습니다. |
| `기기 정보를 확인할 수 없습니다` / `세션 정보를 확인할 수 없습니다` | 처리 가능한 조회 상태가 아닙니다. 제공 UI의 상태와 서버 응답을 확인합니다. |
| `네트워크 오류: ...` / `AI 연결을 확인할 수 없습니다...` | 연결 또는 응답을 확인하지 못했거나 오류가 일반화됐습니다. 표시 코드와 연결 상태를 확인합니다. 제공 UI가 네트워크 원인을 전달하는지는 별도 확인이 필요합니다. |
| `권한 준비 중: ...` / `인증 및 접근 제한: ...` | 계정·앱 권한 준비 또는 인증·접근 문제가 있을 수 있습니다. 담당자에게 확인하고 비밀값은 공유하지 않습니다. |
| `사용량 및 이용 한도: ...` / `이용 시간 외: ...` / `요청 제한: ...` | 사용량·시간·요청 제한 상태입니다. 담당자에게 한도와 이용 시간을 확인합니다. |
| `시간 초과: ...` / `점검 취소됨: ...` | 응답 시간 초과 또는 요청 취소입니다. 이전 결과를 새 결과로 보지 말고 필요하면 직접 다시 점검합니다. |
| `사용 가능한 모델 없음: ...` | 이용 가능한 모델을 확인하지 못했습니다. 담당자에게 설정을 확인합니다. 사건 설명 성공이 아닙니다. |
| `AI 설명 실패: ...` / `AI 설명 자료가 없습니다...` | 설명 요청 실패 또는 데이터 부재입니다. 오류와 선택 기록을 확인합니다. 기록은 그대로이며 설명을 사실로 인용하지 않습니다. |
| `근거 불일치` / `AI가 이미 실행했다고 답한 설명은 쓸 수 없습니다` | 근거가 사건과 맞지 않거나 실행 완료를 주장하는 설명입니다. 원천을 확인하고 내용을 지어내지 않습니다. |
| `서버에 전달 중(executing)` / `서버 접수·처리 중(pending)` | 처리 중이고 결과는 아직 확인되지 않았습니다. 완료·성공으로 표현하지 않습니다. |
| `결과 불명(unknown)` / `실패(failed)` / `거절(denied)` / `요청 처리 안 됨(error)` | 서로 다른 결과 상태입니다. 원래 코드를 확인하고 성공 또는 효과 없음으로 바꾸어 말하지 않습니다. |
| `조회 실패(error)` / `일부 조회 실패(partial)` / `조회 확인 불가(unverifiable)` | 취약점 조회 실패·부분 확인·확인 불가입니다. 취약점 없음으로 해석하지 않습니다. |

`표시할 기록이 없습니다`, `등록된 기기가 없습니다`, `현재 연결된 세션이 없습니다`, `주의할 알림이 없습니다`, `알려진 항목 없음(none_found)`은 빈 결과이지 실패 문구가 아닙니다.

## 5. 실제 확인 범위와 기다림(UNV)

기존 실행 기록은 Windows 11, Node.js `v24.20.0`에서 `npm run check`, 데모 서버 및 일부 로컬 화면 관찰을 기록하고 있습니다. 13~15단계의 데모 결과는 **예제 자료**로 표시했으며 실제 SDP/XDR 연결로 보지 않습니다. 이 문서 편집 중 기록된 관찰을 다시 실행하거나 브라우저에서 독립 확인하지 않았습니다.

### 기다림(UNV)

- 실제 SDP 접속·XDR 서버에서 사용자·기기·세션·경보를 받는 연결.
- CLCO AI 실서버 권한, 실제 사건 설명 호출 및 네트워크 오류 코드 전달.
- 19단계의 실제 원천 조치 집행, 사람 확인, 처리 결과와 효과 관측.
- 운영자 설정 파일을 이용한 외부 호스트 연결 및 네트워크를 통한 전체 취약점 확인 범위.

## 6. 데이터 백업 및 복원 계획

**백업 대상:** `student/extension.mjs`, `docs/STUDENT_GUIDE.md`, `docs/NEW_ENVIRONMENT_RUN_LOG.md`만 학생 자료로 보존합니다. `.env`, 인증서, 개인키, 토큰, 비밀번호 및 운영자 설정은 복사하지 않습니다. 제공 파일은 저장소에서 다시 받을 수 있으므로 학생 백업에 포함하지 않습니다.

**백업 시점:** 단계 작업 후, 제공 스타터 업데이트·환경 교체·문제 해결·복원 전에 백업합니다. 원격 저장소의 커밋과 별도로 로컬 사본을 보관합니다.

**백업 절차:** `on-client` 폴더에서 아래 명령으로 프로젝트 밖의 새 백업 폴더에 지정 파일만 복사합니다. 같은 경로가 이미 있으면 덮어쓰지 말고 새 이름을 사용합니다.

```powershell
$backupDir = Join-Path $HOME ("mowoongga-backup-" + (Get-Date -Format 'yyyyMMdd_HHmmss'))
New-Item -ItemType Directory -Path $backupDir
Copy-Item .\student\extension.mjs -Destination $backupDir
Copy-Item .\docs\STUDENT_GUIDE.md, .\docs\NEW_ENVIRONMENT_RUN_LOG.md -Destination $backupDir
```

복사 후 파일과 백업 위치를 확인하고 비밀정보가 섞이지 않았는지 살펴봅니다. 프로젝트 전체 복사나 `git add .`는 백업 절차로 사용하지 않습니다.

**복원 순서:**
1. 기존 작업 폴더를 삭제·초기화하지 말고 보존합니다. 새 폴더에 저장소를 복제합니다.
2. 새 복제본의 학생 파일과 백업을 비교해 필요한 파일만 선택합니다.
3. `student/extension.mjs`를 복원하고, 이어서 두 문서를 각각 `docs/`의 같은 이름으로 복원합니다. 더 최신 파일을 덮어쓰지 않도록 복사 전후 내용을 확인합니다.
4. `on-client`에서 `npm run check`를 실행합니다. 실행 결과를 확인하지 않았다면 복원을 완료했다고 기록하지 않습니다.
5. 인증·연결 설정은 복원하지 않습니다. 필요한 설정은 담당자에게 안전한 방법으로 다시 요청합니다.

**복구할 수 없는 범위:** 만료된 세션·일회용 확인 번호·만료 또는 회수된 승인/조치 티켓·서버에서 사라진 처리 중 상태·브라우저 메모리 화면은 파일 백업으로 되살릴 수 없습니다. 외부 서버의 기록·권한·조치 결과도 복원되지 않으며 원천 서버나 담당자 절차로 다시 확인해야 합니다.

## 7. 버전 차이

- `package.json`의 `engines.node`는 `24.19.0`으로 지정되어 있습니다. 반면 실행 도구와 안내 문서는 Node.js 22~24 지원 범위를 안내합니다. 실행 기록의 `v24.20.0`은 22~24 범위 안이지만 정확히 `24.19.0`은 아닙니다. 따라서 package.json에 지정된 버전 자체로 시험했다고 말할 수 없습니다.
- `docs/FINAL_PRODUCT_GUIDE.md`의 기준 명세는 `starter 0.2.9`로 표기되고, 현재 `package.json`은 `0.2.11`입니다. 버전이 다르며, `0.2.11`이 `0.2.9`의 명세를 완전히 충족한다고 별도로 검증한 것은 아닙니다.
- 실행 결과의 재검증은 이번 편집에서 하지 않았습니다. 확인하지 않은 테스트·서버 연결·공식 판정을 새로 추가하지 않습니다.

비밀번호·개인키·토큰 또는 그 밖의 비밀값을 문서나 백업에 넣지 마세요. 도움정보를 공유하기 전에도 비밀값 포함 여부를 직접 확인하세요.
