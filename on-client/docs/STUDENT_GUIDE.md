# 모웅가(mowoongga) 학생 설명서

이 문서는 학생 확장 코드와 제공 코드의 **확인한 구조·화면 역할·실행 절차**를 설명합니다. 제공된 기존 코드는 수정하지 않았습니다. 저장소 소스 코드와 설정에 부합하는 내용을 기준으로 작성되었으며, 실제 로컬에서 확인한 내용과 원천 서버 대기(UNV) 항목을 명확히 구분합니다.

## 1. 설치 및 실행 순서 (Run Instructions)

새 PowerShell 창에서 그대로 따라 할 수 있도록 소스 코드(`src/server.mjs`, `package.json`, `README.md`)와 도구 설정에 맞추어 검증된 명령을 기록합니다. 특정 개인 PC의 절대 경로를 고정하지 않고 상대 경로(`on-client`) 또는 환경 변수 기준으로 작성되었습니다.

### 1.1 새 환경(클린 폴더) 설치 및 준비 절차
새로운 PC 또는 빈 폴더에서 프로젝트를 시작할 때 아래 절차를 차례대로 실행합니다.

```powershell
# 1. 새 빈 폴더 생성 및 이동
mkdir C:\temp\mowoongga-clean
cd C:\temp\mowoongga-clean

# 2. 저장소 복제 (Git Clone)
git clone https://github.com/dldaudlee36/Fightvac.git .

# 3. 앱 폴더로 이동
cd on-client
```

### 1.2 실행 및 검사 명령

1. **학생 코드 구문 검사 (실행 확인 완료)**:
   ```powershell
   cd on-client
   npm run check
   ```
   - 저장소 루트에서 앱 폴더(`on-client`)로 이동한 뒤 실행합니다. (이미 `on-client` 폴더인 경우 `npm run check`만 실행)
   - `node --check student/extension.mjs`를 실행하여 학생 구현 코드의 문법 오류가 없음을 현재 커밋에서 확인했습니다.

2. **예제(데모) 서버 실행 (실행 확인 완료)**:
   ```powershell
   npm run demo
   ```
   - 또는 `node src/server.mjs --demo`
   - 서버 코드는 `ON_PORT` 환경변수가 없으면 기본적으로 포트 `5189`를 사용하며 `127.0.0.1`에 바인딩합니다.
   - 브라우저로 `http://127.0.0.1:5189`에 접속하여 예제 화면을 확인합니다. (콘솔 로그: `케셰브 예제: http://127.0.0.1:5189`)

3. **기본 실행 (연결 없음 상태)**:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
   ```
   - 또는 `npm start` (`node src/server.mjs`)
   - 외부 호스트 설정이 없는 기본 상태에서는 연결 없음(`disconnected`) 모드로 기동됩니다 (`http://127.0.0.1:5189`).

4. **실제 외부 호스트 연동 실행**:
   - `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NativeHostConfig "<경로>"`
   - 실제 운영자 외부 호스트 설정 파일은 아직 발급받지 않았으므로: **확인 필요**

5. **종료 방법**:
   - 실행 중인 터미널 창에서 `Ctrl + C`를 누릅니다.

## 2. 구성도

아래는 소스에서 확인한 4개 주요 구성 요소입니다.

```text
┌──────────────────────────────────────────────┐
│ 브라우저 (Client UI)                          │
│ on-client/public/index.html                 │
│ on-client/student/extension.mjs              │
└──────────────────────┬───────────────────────┘
                       │ 로컬 HTTP 요청
                       ▼
┌──────────────────────────────────────────────┐
│ 앱 서버 (App Server)                         │
│ on-client/src/server.mjs                    │
│ 기본 주소: http://127.0.0.1:5189             │
└──────────────────┬───────────────────┬───────┘
                   │                   │
                   ▼                   ▼
┌────────────────────────────────┐  ┌────────────────────────────────┐
│ 기존 접속·XDR 서버 (SDP 엔진)   │  │ CLCO 수업용 AI 게이트웨이      │
│ on-client/src/engine/sdp-host.mjs│  │ on-client/src/ai/service.mjs   │
│ on-client/src/actions/sdp-     │  │ on-client/vendor/clco-http.mjs │
│ action-engine.mjs              │  │ 게이트 주소:                   │
└────────────────────────────────┘  │ https://ai-classroom-gateway-  │
                                    │ production.up.railway.app      │
                                    └────────────────────────────────┘
```

- **브라우저**는 제공 UI를 표시하고 학생 렌더러를 불러옵니다. 학생 표시 코드는 `on-client/student/extension.mjs`에 있습니다.
- **앱 서버**는 로컬 화면과 서버 API를 연결합니다. 소스에는 기본 포트 `5189`와 loopback 주소 `127.0.0.1`이 설정되어 있습니다.
- **기존 접속·XDR 서버**는 사용자·기기·세션, 업무 앱 접속 판정과 기록의 원천입니다. 연결 설정이나 결과를 실제로 확인하지 못하면 실연결 성과로 간주하지 않습니다.
- **CLCO 수업용 AI**는 앱 서버가 사용하는 AI 전송 계층의 대상입니다. 게이트 주소는 소스의 기본 주소이며, 실제 계정 권한이나 연결 성공을 확인했다는 뜻은 아닙니다.

## 3. 학생 렌더링 함수

아래 설명은 `on-client/student/extension.mjs`의 현재 코드에 근거합니다. 함수가 구현되어 있다는 사실만으로 실제 화면에서 동작했다고 단정하지 않습니다.

| 함수 | 화면에 보여 주는 내용 |
|---|---|
| `renderIdentity` | 사용자 이름, 기기 이름과 상태, 세션 상태를 표시합니다. 기기·세션 상태는 한국어 뜻과 원래 상태 코드를 함께 보여 주며, 불러오는 중·연결 실패와 예제 자료/연결 없음/확인 불가 모드도 구분합니다. |
| `renderDecision` | 선택한 업무 앱에 대한 접속 판정, 이유, 확인 시각, 앱 식별자를 표시합니다. 요청 실패는 서버의 `deny` 판정과 별개라고 명시하고, 알 수 없는 판정은 허용으로 취급하지 않습니다. |
| `renderEvents` | 보안 기록을 최신 시각 순으로 정렬하고 종류·업무 앱·접속 상태 필터를 제공합니다. 각 기록의 상세 보기에는 근거·규칙·상태와 지원되지 않는 조치 안내를 표시하며, 실제 조치를 실행하는 버튼은 만들지 않습니다. |
| `renderStatus` | 기기·세션의 불러오는 중, 빈 목록, 실패 상태와 알림을 구분해 보여 줍니다. 진단 화면은 제한된 진단 필드와 도움정보 복사 버튼을 제공하며, 복사는 버튼을 눌렀을 때만 시도합니다. |
| `renderAiConnection` | AI 연결 점검 전·진행 중·성공·실패를 구분하고, 권한·인증·사용량·시간 초과·네트워크 등 오류 코드를 범주별 안내로 연결합니다. 모델 목록 점검은 실제 사건 설명 성공이 아니라고 알리고 수동 재점검을 안내합니다. |
| `renderExplanation` | 선택한 사건의 AI 설명을 참고용으로 표시하고, 인용 근거 ID가 사건 기록에 있는지 확인합니다. 규칙·확인 불가 상태·조치 제안을 구분하며, 근거 불일치나 실행 완료를 주장하는 설명은 성공 결과로 보여 주지 않습니다. |
| `renderAction` | 조치의 미실행·준비·서버 처리 중·성공·거절·실패·결과 불명 상태를 원래 코드와 함께 구분합니다. 효과 관측이 확인된 경우에만 성공으로 표시하며, 이 렌더러 자체에는 실행 버튼이 없습니다. |
| `renderVulnerabilities` | 전체 취약점 조회 상태와 lock 파일 정보, 패키지별 설치 버전·조회 상태·출처·확인 시각을 표시합니다. 취약점 ID와 수정 시각을 보여 주며, 조회 실패나 확인 불가를 취약점 없음으로 바꾸지 않습니다. |

## 4. 화면 실패·확인 불가 문구

문구의 괄호 안 값은 실제 응답에 따라 달라질 수 있습니다. 화면 문구만으로 원인을 확정할 수 없는 경우에는 원인을 추정하지 말고, 표시된 오류와 해당 영역의 상태를 함께 확인합니다.

| 화면 실패·확인 불가 문구 | 뜻·가능한 원인 | 확인할 것 |
|---|---|---|
| `연결 실패: ...` | 사용자 정보 조회가 오류 상태로 반환됐습니다. 네트워크·서버·기존 연결 중 무엇이 원인인지는 표시된 오류 내용만으로 확인해야 합니다. | 앱 서버가 실행 중인지, 화면의 오류 메시지가 무엇인지 확인합니다. 기기·사용자 정보를 정상으로 간주하지 않습니다. |
| `요청 실패: ... (요청/네트워크 실패이며, 서버의 접근 거부(deny) 판정이 아닙니다.)` | 앱 접근 판정 요청 자체가 실패했습니다. 이는 `deny` 판정이 아닙니다. | 선택한 업무 앱과 오류 내용을 확인하고, 실패를 접근 거부 결과로 제출하지 않습니다. |
| `확인 불가 (unknown) — 허용되지 않음 / 판정 불명` | 판정 값이 없거나 알려진 `allow`, `deny`, `challenge`가 아닙니다. | 원천 판정 응답을 확인합니다. 허용으로 처리하거나 추측하지 않습니다. |
| `기록을 불러오지 못했습니다: ...` | 기록 조회가 오류 상태로 반환됐습니다. 빈 목록과는 다릅니다. | 오류 메시지와 서버 응답을 확인합니다. 오류 화면을 “기록 없음”으로 해석하지 않습니다. |
| `기록을 확인할 수 없습니다` | 기록 조회 상태가 처리 가능한 `loading`, `error`, `ok` 중 하나로 확인되지 않았습니다. | 제공 UI가 전달한 상태 값과 서버 응답을 확인합니다. |
| `선택한 조건에 맞는 기록이 없습니다` | 선택한 필터 조합에 맞는 기록이 없습니다. 기록 전체 조회 실패를 뜻하지는 않습니다. | 필터를 확인하거나 전체 조건으로 바꿔 살펴봅니다. |
| `기기 정보를 불러오지 못했습니다: ...` / `세션 정보를 불러오지 못했습니다: ...` | 해당 정보 조회에 실패했습니다. 오류 코드나 메시지가 시간 초과를 나타낼 수도 있습니다. 이는 빈 목록과 다릅니다. | 오류 내용과 서버 응답을 확인하고, 위쪽 다시 불러오기 버튼을 직접 누릅니다. 자동 재요청을 기대하지 않습니다. |
| `기기 정보를 확인할 수 없습니다` / `세션 정보를 확인할 수 없습니다` | 조회 결과의 상태가 코드에서 처리 가능한 상태로 확인되지 않았습니다. | 제공 UI가 전달한 상태와 해당 API 응답을 확인합니다. |
| `진단 정보를 불러오지 못했습니다` | 진단 조회가 오류 상태입니다. 이 화면은 상세 오류 코드를 표시하지 않습니다. | 서버의 진단 요청 결과나 도움정보를 확인하고, 오류 원인을 추측하지 않습니다. |
| `AI 연결을 확인할 수 없습니다. 잠시 후 다시 시도하세요.` | AI 연결 오류 코드가 렌더러의 알려진 분류에 없거나 일반 오류로 전달됐습니다. | 오류 코드·메시지를 확인하고, 계정·앱 권한 또는 연결 상태를 담당자에게 확인합니다. 다시 점검은 화면 버튼으로 직접 합니다. |
| `권한 준비 중: ...` | 계정 연결 또는 앱 권한 준비가 완료되지 않았거나 점검 도중 변경됐을 수 있습니다. | 담당자에게 계정 연결과 앱 권한 확인을 요청합니다. |
| `인증 및 접근 제한: ...` | 인증이 필요하거나 접근이 차단됐을 수 있습니다. | 계정 연결 상태를 확인하고 담당자에게 문의합니다. 비밀값을 채팅에 붙여 넣지 않습니다. |
| `사용량 및 이용 한도: ...` | 반 사용량 또는 AI 이용 한도에 걸렸을 수 있습니다. | 담당자에게 반의 사용량과 한도를 확인합니다. |
| `이용 시간 외: ...` / `요청 제한: ...` | 이용 시간이 닫혔거나 요청이 잠시 제한됐을 수 있습니다. | 현재 이용 가능 시간과 안내된 제한 상태를 확인합니다. 재시도는 직접 요청합니다. |
| `시간 초과: AI 요청 시간이 초과되었습니다...` | AI 연결 점검 응답이 제한 시간 내 확인되지 않았습니다. | 네트워크와 점검 상태를 확인하고, 위쪽 점검 버튼을 직접 눌러 다시 확인합니다. |
| `네트워크 오류: ...` | AI 서버에 연결할 수 없었거나 서버 응답을 확인하지 못했습니다. 표시 코드가 일반화되면 원인을 더 구분할 수 없습니다. | 앱 서버·네트워크와 표시된 오류 코드를 확인합니다. 제공 UI가 네트워크 원인을 전달했는지는 별도 확인이 필요합니다. |
| `점검 취소됨: ...` | AI 연결 점검 요청이 취소됐습니다. 이전 결과가 현재 상태라는 뜻은 아닙니다. | 현재 화면의 상태를 기준으로 하고, 필요하면 직접 점검을 다시 요청합니다. |
| `사용 가능한 모델 없음: ...` | 현재 연결에서 사용할 모델 목록을 확인하지 못했거나 목록이 비어 있습니다. | 담당자에게 허용된 모델 설정을 확인합니다. 이것만으로 AI 사건 설명이 성공했다고 보지 않습니다. |

## 5. 확인된 범위와 기다림(UNV) — 정직한 지원 범위

### 5.1 현재 커밋에서 확인한 범위 (로컬 개발 환경)
- **학생 코드 구문 검사:** `npm run check` (`node --check student/extension.mjs`)를 실행하여 문법 오류가 없음을 확인했습니다.
- **로컬 서버 기동 및 포트 바인딩:** `src/server.mjs`가 기본 포트 `5189`(`127.0.0.1:5189`)에서 예제(demo) 및 기본 모드로 기동됨을 확인했습니다.
- **학생 렌더링 함수 구현:** `student/extension.mjs`의 8개 함수가 DOM 구성, 상태 분기, 민감 정보 은닉, 무효 응답 거부 로직을 갖추고 있음을 단위 테스트로 확인했습니다.

### 5.2 기다림(UNV) — 아직 실제로 확인하지 못한 것 (미확인)
UNV는 실제 원천 서버 또는 외부 서비스 연동 증거가 없어 확인을 기다리는 항목입니다. 소스 코드에 경로와 주소가 적혀 있다는 것만으로 실서비스 연동을 확인한 것은 아닙니다.

- **기존 접속·XDR 원천 서버 실연결:** 실제 운영 SDP 서버와 물리적으로 통신하여 실제 사용자·기기·세션 데이터 및 XDR 기록을 수신하는 동작은 미확인(UNV)입니다.
- **CLCO 수업용 AI 실서버 권한 및 호출:** 실제 수업 계정의 모델 목록 응답, 권한 상태 및 라이브 AI 사건 설명 호출 경로는 운영 측 게이트 개방 대기(UNV) 상태입니다.
- **네트워크 오류 세부 전달:** 학생 렌더러에 `NETWORK_ERROR`와 `AI_REQUEST_UNVERIFIED` 안내를 구현했으나, 제공 UI가 실제 네트워크 장애 코드를 그대로 전달하는지는 미확인(UNV)입니다.
- **원천 조치 집행 및 실제 효과:** 렌더러는 상태를 표시할 뿐이며, `supportedActions`가 비어 있어 실제 조치 요청·원천 서버 집행·효과 관측(`effectApplied: true`)은 미완료(UNV) 상태입니다.
- **외부 호스트 설정 연동 명령:** `-NativeHostConfig`, `-SdpHostConfig` 옵션을 통한 실제 호스트 실행은 외부 설정 파일 미제공 상태이므로 확인 필요(미확인)입니다.
- **취약점 조회 외부 통신:** 허용된 공개 패키지 외의 비공개 패키지는 외부로 전송되지 않으며, 실시간 OSV 대량 조회는 미확인(UNV)입니다.

## 6. 데이터 백업 및 복원 계획 (Data Preservation Plan)

단순한 Git 커밋 외에도 환경 손상이나 비정상 종료로부터 학생 데이터와 학습 성과를 온전히 보존하기 위한 구체적인 계획입니다.

### 6.1 보존할 데이터와 위치
- **학생 구현 소스:** `student/extension.mjs` (학생이 13~20단계에 걸쳐 구현한 8개 필수 렌더러 함수)
- **학생 작성 문서:** `docs/STUDENT_GUIDE.md`, `docs/NEW_ENVIRONMENT_RUN_LOG.md`
- **로컬 설정 파일:** `.env` (존재할 경우 로컬 환경 설정 보존, 비밀값 제외)
- *(구분)* 제공 코드(`src/**`, `public/**`, `tools/**`, `package.json` 등)는 Git 저장소 및 원본 스타터 패키지에서 즉시 재제공되므로 학생 데이터와 구분하여 관리합니다.

### 6.2 백업 시점
- 단계별 구현 완료 직후 및 Git 커밋 직전/직후
- 새 빈 폴더에서의 복제(clone) 및 재현 시험 수행 전
- 운영 측의 스타터 패키지 업데이트 또는 제공 파일 갱신 안내를 받기 전
- 소스 코드 롤백이나 문제 해결을 시도하기 전

### 6.3 안전한 백업 절차
1. **Git 원격 저장소 백업**:
   ```powershell
   git add student/extension.mjs docs/STUDENT_GUIDE.md docs/NEW_ENVIRONMENT_RUN_LOG.md
   git commit -m "Backup student code and documentation"
   git push origin master
   ```
2. **로컬 안전 디렉터리 백업 (Git 외 별도 보존)**:
   Git 저장소 손상이나 오작동에 대비해 외부 안전 폴더로 복사본을 보관합니다.
   ```powershell
   $backupDir = "$HOME\mowoongga-backup\$(Get-Date -Format 'yyyyMMdd_HHmmss')"
   New-Item -ItemType Directory -Path $backupDir -Force
   Copy-Item -Path "student\extension.mjs" -Destination $backupDir -Force
   Copy-Item -Path "docs\STUDENT_GUIDE.md", "docs\NEW_ENVIRONMENT_RUN_LOG.md" -Destination $backupDir -Force
   if (Test-Path ".env") { Copy-Item -Path ".env" -Destination $backupDir -Force }
   ```

### 6.4 복원 절차
작업 디렉터리가 손상되었거나 새 환경으로 전환할 경우:
1. 새 빈 폴더를 준비하고 원격 저장소를 클론합니다:
   ```powershell
   git clone https://github.com/dldaudlee36/Fightvac.git <새_폴더>
   cd <새_폴더>\on-client
   ```
2. Git 최신 커밋 상태를 확인하고, 필요한 경우 로컬 백업 폴더에서 학생 파일을 복사하여 복원합니다:
   ```powershell
   Copy-Item -Path "$backupDir\extension.mjs" -Destination "student\extension.mjs" -Force
   Copy-Item -Path "$backupDir\*.md" -Destination "docs\" -Force
   ```
3. 복원 후 구문 검증 명령으로 무결성을 확인합니다:
   ```powershell
   npm run check
   ```

아래의 일회성·휘발성 런타임 데이터는 백업 대상이 아니며 복원할 수 없습니다. 복원 후에는 필요 시 브라우저 화면에서 새롭게 발급·조회해야 합니다:
