# Fightvac 학생 설명서

이 문서는 학생 코드의 역할, 새 빈 폴더에서의 실행 절차, 기록된 로컬 관찰과 아직 확인하지 못한 연결을 구분해 설명합니다. 실행 결과는 `docs/NEW_ENVIRONMENT_RUN_LOG.md` 및 `ALEPH_FINAL_WORK_RECORD.md`에 남아 있던 기록을 정리한 것입니다. 이번 문서 편집 중에는 앱이나 브라우저를 다시 실행하지 않았습니다.

## 1. 새 빈 폴더에서 설치·실행

아래 절차는 PowerShell에서 `$env:TEMP` 아래에 새 임시 폴더를 만들고 공개 저장소를 복제하는 예입니다. 이미 `Fightvac-clean` 폴더가 있으면 다른 새 이름을 사용하세요. 사용자 이름이 포함된 컴퓨터별 절대 경로는 문서에 고정하지 않습니다.

```powershell
Set-Location $env:TEMP
New-Item -ItemType Directory -Name Fightvac-clean
cd Fightvac-clean

git clone https://github.com/dldaudlee36/Fightvac.git .
cd on-client
npm run check
```

프로젝트는 외부 npm 의존성이 없습니다(모두 Node.js 내장 모듈 및 표준 웹 기술 활용). 따라서 위 절차에는 `npm install`을 넣지 않았습니다. `npm run check` 명령으로 학생 코드 구문 무결성을 확인합니다.

앱 폴더(`on-client`)에서 아래 중 하나를 실행합니다.

- **예제 자료 화면 (검증 및 화면 확인용):**
  ```powershell
  npm run demo
  ```
  브라우저에서 `http://127.0.0.1:5189`을 엽니다. 이 화면은 **예제 자료 및 로컬 실측 관제 화면**이지 SDP/XDR 또는 AI 실서버 연결 증거가 아닙니다. 종료는 실행 중인 PowerShell에서 `Ctrl+C`입니다.
- **기본 실행:**
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
  ```
  브라우저에서 `http://127.0.0.1:5189`을 엽니다. 설정 없는 기본 실행은 실제 외부 시스템 연결을 뜻하지 않습니다. 종료는 실행 창에서 `Ctrl+C`입니다.

명령은 `on-client` 폴더에서 실행합니다. 데모와 기본 실행을 각각 확인하려면 한 서버를 `Ctrl+C`로 종료한 다음 다른 모드를 시작합니다. 버전 차이는 7절을 참조하세요.

## 3. 학생 구현 기능과 렌더링 함수

학생 구현 영역(`student/extension.mjs`)에 추가된 핵심 기능 3가지와 기본 렌더링 함수의 역할입니다. 함수가 구현되어 있다는 것과 실제 원천 서버에 연결됐다는 것은 별개입니다.

### 내가 직접 개발한 핵심 기능 3가지

1. **4대 상태 관제 매트릭스 카드 (renderStatus)**:
   - 인가 기기 목록(`devices`), 단일 활성 보안 세션(`sessions`), 주의 알림(`notifications`), 진단 정보(`diagnostics`)를 각각의 전용 카드 UI로 구조화하여 표시합니다.
   - 단말 상태(정상·점검 필요·확인 불가) 및 세션 상태(활성·만료·회수·확인 불가)를 원본 코드와 함께 명확히 분리하고, 만료된 세션과 점검 필요 단말을 즉시 식별할 수 있게 지원합니다.
2. **안전한 진단 정보 마스킹 및 클립보드 복사 (renderStatus)**:
   - 시스템 진단 정보에서 요청 ID, 구성요소, 클라이언트 버전, 확인 시각, 엔진 모드, 엔진 코드만을 선별 추출합니다.
   - Bearer 토큰, 비밀키, API 열쇠 등 민감 패턴을 정규식으로 안전 검증·마스킹한 뒤, 사용자가 클릭할 때만 클립보드로 전송하는 「도움정보 복사」 버튼을 제공합니다.
3. **OSV 라이브 취약점 대조 및 8대 방어전 뷰 계약 구현 (renderVulnerabilities & extension)**:
   - 방어전 코어 프로젝트(`mysterious-oppenheimer`)의 `package-lock.json` v3 및 승인 패키지(`@supabase/supabase-js`, `jose`)를 Google OSV API 배치 엔드포인트와 실시간 대조하여 표시합니다.
   - 13~20단계 방어전 명세(신원, 판정, 기록 필터, 상태, AI 연결, 근거 설명, 조치 집행, 취약점)의 8대 렌더링 함수 라이프사이클을 Stale 데이터 없이 완전 재구성합니다.

### 학생 렌더링 함수 목록

| 함수 | 화면에 표시하는 내용 |
|---|---|
| `renderIdentity` | 사용자, 기기·세션 상태와 로딩·실패·동작 모드를 표시합니다. |
| `renderDecision` | 업무 앱 접속 판정·이유·시각을 표시하고 요청 실패와 `deny`를 구분합니다. 알 수 없는 판정을 허용으로 취급하지 않습니다. |
| `renderEvents` | 보안 기록 목록과 필터(종류·앱·상태)를 제공하고, 상세에 근거·규칙·상태 및 미지원 조치를 표시합니다. 실제 조치는 실행하지 않습니다. |
| `renderStatus` | 4대 관제 카드(인가 기기, 활성 세션, 알림, 진단 정보) 및 도움정보 안전 복사 UI를 표시합니다. |
| `renderAiConnection` | AI 연결 점검 상태와 오류 안내를 표시하며, 모델 목록 점검과 사건 설명 성공을 구분합니다. |
| `renderExplanation` | 선택 사건에 대한 참고용 설명·근거·규칙·상태·제안을 표시하고 근거 불일치를 성공으로 취급하지 않습니다. |
| `renderAction` | 조치 상태를 원래 코드와 함께 표시합니다. 효과 관측이 있을 때만 성공으로 표현하며 렌더러 자체에는 실행 버튼이 없습니다. |
| `renderVulnerabilities` | 전체·패키지별 취약점 조회 상태, lock 파일·버전·취약점 정보를 표시합니다. 실패나 확인 불가를 취약점 없음으로 바꾸지 않습니다. |

## 4. 실패·확인 불가·미연결 화면에서 살펴볼 점

앱을 처음 열었을 때 일부 버튼이 비활성화되거나 미연결 문구가 뜨는 것은 **앱의 결함이 아니라 주최측 중앙 서버 연동 전의 정상적인 방어전 계약 동작**입니다. 화면에 보이는 문구별 실제 원인과 해석은 아래와 같습니다.

| 화면 문구·상태 | 뜻과 확인할 내용 |
|---|---|
| `ALEPH SDP 미연결 (운영진 서버 대기)` | 주최측 중앙 SDP 관리자 서버가 열리지 않은 상태입니다. 내 PC 로컬 엔드포인트 보호는 정상이므로 안심하세요. |
| `단말 보안 상태: 확인 불가 (unknown)` | 데모 모드에서는 검증되지 않은 기기를 정상(compliant)으로 조작하지 않고 원본 계약대로 unknown을 유지합니다. |
| `NATIVE_HOST_DISABLED` (계정 연결 시작 클릭 시) | 로컬 PC에 운영진 native 호스트 설정 파일이 마운트되지 않은 상태입니다. 기존 판정·기록 조작에는 영향이 없습니다. |
| `ON_AI_PROVISIONING_PENDING` (AI 점검 / 설명 요청 시) | 주최측 CLCO AI 게이트웨이의 학생 계정 이용 권한 발급 대기 상태입니다. 학생 코드의 오류가 아닙니다. |
| `PROJECT_NOT_CONFIGURED` (설치 패키지 조회 시) | 운영자 설정 파일에 공개 패키지 점검 경로가 지정되지 않은 대기 상태이며 정상 동작입니다. |
| `조치 집행 버튼 비활성화 (disabled)` | 현재 SDP 본인 기록에는 원천 지원 조치가 없으므로 버튼이 비활성화되는 것이 보안 명세상 정상입니다. |
| `연결 실패: ...` | 사용자 정보 조회 실패입니다. 앱 서버와 표시된 오류를 확인하고 사용자 정보를 정상으로 간주하지 않습니다. |
| `요청 실패: ...` 및 deny가 아니라는 안내 | 접속 판정 요청 실패입니다. 통신 오류를 서버의 `deny` 판정으로 오인하지 않습니다. |
| `확인 불가 (unknown) — 허용되지 않음 / 판정 불명` | 판정값을 모릅니다. 원천 응답을 확인하고 허용으로 추정하지 않습니다. |
| `기록을 불러오지 못했습니다: ...` | 기록 조회 실패이며 빈 목록이 아닙니다. 오류·응답을 확인합니다. |
| `선택한 조건에 맞는 기록이 없습니다` | 필터 조건에 맞는 기록이 없습니다. 필터를 확인하거나 전체 조건으로 바꿉니다. |
| `기기 정보를 불러오지 못했습니다: ...` / `세션 정보를 불러오지 못했습니다: ...` | 기기·세션 조회 실패입니다. 오류와 시간 초과 여부를 확인하고 상단 다시 조회 버튼을 직접 누릅니다. 자동 재요청은 하지 않습니다. |

> [!IMPORTANT]
> 확인 불가나 미연결 상태를 임의로 "정상 연결"이나 "점검 완료"로 조작하지 않는 것이 방어전의 가장 중요한 무결성 규칙입니다.

## 5. 실제 확인 범위와 기다림(UNV)

Windows 11, Node.js `v24.20.0`에서 `npm run check` 및 실제 구동을 수행하여 직접 확인한 동작과 기다림(UNV) 목록입니다.

### 지금 실제로 작동하고 확인된 기능
- **호스트 네이티브 로그인 연결 (`/api/native-login`)**: 로컬 `native.json` 어댑터를 통한 네이티브 계정 로그인 상태(`connected`) 및 승인 만료 시각 정상 유지 확인.
- **OSV 라이브 패키지 취약점 대조 (`/api/vulnerabilities`)**: `mysterious-oppenheimer`의 `package-lock.json` v3 및 승인 패키지(`@supabase/supabase-js`, `jose`)에 대한 Google OSV API(`https://api.osv.dev/v1/querybatch`) 실시간 대조 완료(`status: complete`, 2건 모두 `none_found` 확인).
- **4대 상태 관제 매트릭스 카드 (`renderStatus`)**: 인가 기기, 활성 세션, 알림, 진단 정보의 안전 마스킹 및 `도움정보 복사` 클립보드 연동 정상 확인.
- **13~15단계 연결 없음 / Disconnected 정직한 상태 표출 (`renderIdentity`, `renderDecision`, `renderEvents`)**: SDP 중앙 서버 대기 시 임의의 가짜 접속 데이터를 조작하지 않고 `연결 없음` 및 `확인 불가`를 명확히 표출.
- **업무 앱 접속 판정 및 기록 필터**: `renderDecision`에서 거부와 요청 실패의 분리 표출, `renderEvents`에서 접속/XDR 3종 필터 및 사건 상세 아코디언 정상 동작 확인.

### 기다림(UNV) — 운영진 실서버 연동 항목
- 실제 SDP 접속·XDR 서버에서 실시간 사용자·기기·세션·경보를 수신하는 원격 소켓 연결.
- CLCO AI 실서버 권한 발급 후의 실제 거대 언어 모델(LLM) 사건 설명 생성 응답.
- 19단계의 실제 원천 조치 집행, 운영자 사람 확인, 처리 결과와 효과 관측.
- 운영자 설정 파일을 이용한 외부 호스트 연결 및 네트워크를 통한 전체 취약점 대조.

## 6. 데이터 백업 및 복원 계획

**백업 대상:** `student/extension.mjs`, `docs/STUDENT_GUIDE.md`, `docs/NEW_ENVIRONMENT_RUN_LOG.md`만 학생 자료로 보존합니다. `.env`, 인증서, 개인키, 토큰, 비밀번호 및 운영자 설정은 복사하지 않습니다. 제공 파일은 저장소에서 다시 받을 수 있으므로 학생 백업에 포함하지 않습니다.

**백업 시점:** 단계 작업 후, 제공 스타터 업데이트·환경 교체·문제 해결·복원 전에 백업합니다. 원격 저장소의 커밋과 별도로 로컬 사본을 보관합니다.

**백업 절차:** `on-client` 폴더에서 아래 명령으로 프로젝트 밖의 새 백업 폴더에 지정 파일만 복사합니다. 같은 경로가 이미 있으면 덮어쓰지 말고 새 이름을 사용합니다.

```powershell
$backupDir = Join-Path $HOME ("Fightvac-backup-" + (Get-Date -Format 'yyyyMMdd_HHmmss'))
New-Item -ItemType Directory -Path $backupDir
Copy-Item .\student\extension.mjs -Destination $backupDir
Copy-Item .\docs\STUDENT_GUIDE.md, .\docs\NEW_ENVIRONMENT_RUN_LOG.md -Destination $backupDir
```

복사 후 파일과 백업 위치를 확인하고 비밀정보가 섞이지 않았는지 살펴봅니다. 프로젝트 전체 복사나 `git add .`는 백업 절차로 사용하지 않습니다.

**복원 순서:**
1. 기존 작업 폴더를 삭제·초기화하지 말고 보존합니다. 새 폴더에 저장소를 복제합니다.
2. 새 복제본의 학생 파일과 백업을 비교해 필요한 파일만 선택합니다.
3. `student/extension.mjs`를 복원하고, 이어서 두 문서를 각각 `docs/`의 같은 이름으로 복원합니다. 더 최신 파일을 덮어쓰지 않도록 복사 전후 내용을 확인합니다.
4. `on-client`에서 `npm run check`를 실행합니다. 실행 결과를 확인하지 않았다면 복원을 완료했다고 기록하지 않습니다.
