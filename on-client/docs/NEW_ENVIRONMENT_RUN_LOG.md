## 2. 새 환경 사양 및 임시 클린 폴더 절차

- **운영체제:** Windows 11
- **PowerShell:** 버전은 실행 기록에 없음(미확인)
- **Node.js:** `v24.20.0`
- **패키지에 지정된 Node 버전:** `package.json`의 `engines.node`는 `24.19.0`
- **실행 도구 문서 범위:** Node.js 22~24
- **임시 클린 폴더 표기:** `$env:TEMP\mowoongga-clean` (그 안의 앱 폴더는 `$env:TEMP\mowoongga-clean\on-client`). Windows가 이 환경 변수에 실제로 대응시킨 사용자별 전체 경로는 기록에 남아 있지 않아 미확인입니다.

실행 기록에 남은 절차는 아래와 같습니다. 새 임시 위치를 사용하고, 그 폴더가 비어 있는지 확인한 뒤 저장소를 복제합니다. 같은 이름의 폴더가 이미 있다면 임의로 덮어쓰지 말고 새 폴더 이름을 선택합니다.

```powershell
Set-Location $env:TEMP
New-Item -ItemType Directory -Name mowoongga-clean
cd mowoongga-clean
git clone https://github.com/dldaudlee36/Fightvac.git .
cd on-client
npm run check
npm run demo
```

기존 실행 기록은 `npm run check`가 정상 종료했고, `npm run demo` 실행 시 로컬 서버가 포트 `5189`에서 응답하여 `http://127.0.0.1:5189` 요청에 HTTP 200을 반환했다고 적고 있습니다. Demo는 **예제 자료**입니다. 기록에는 절차 도중 데모를 종료한 것으로 적혀 있지만, 종료 시각 및 브라우저에서 직접 확인한 개별 화면은 미기록입니다. 위 명령은 기록된 절차의 설명이며, 이번 수정에서 실행한 명령은 아닙니다.

## 5. 데이터 백업 및 복원 계획

### 백업 대상·시점

- **백업 대상:** 학생 구현 `student/extension.mjs`, 학생 문서 `docs/STUDENT_GUIDE.md`, `docs/NEW_ENVIRONMENT_RUN_LOG.md`.
- **제외:** `.env`, 비밀번호, 개인키, 토큰, 인증서 및 운영자 연결 설정 파일. 비밀값을 Git·문서·백업 명령에 넣지 않습니다. 제공 코드와 앱 의존성은 저장소 원본에서 다시 받으며, 이 학생 자료 백업에 섞지 않습니다.
- **시점:** 각 단계 작업을 마친 뒤, 제공 스타터 업데이트·환경 교체·문제 해결·복원 전에 백업합니다. 원격 저장소의 커밋과 별도로 로컬 사본을 보관합니다.

### 백업 절차

`on-client`에서 프로젝트 밖의 새 백업 폴더를 만들고 필요한 학생 파일만 복사합니다. 동일한 폴더 이름이 이미 있으면 기존 백업을 덮어쓰지 말고 새 이름을 선택합니다.

```powershell
$backupDir = Join-Path $HOME ("mowoongga-backup-" + (Get-Date -Format 'yyyyMMdd_HHmmss'))
New-Item -ItemType Directory -Path $backupDir
Copy-Item .\student\extension.mjs -Destination $backupDir
Copy-Item .\docs\STUDENT_GUIDE.md, .\docs\NEW_ENVIRONMENT_RUN_LOG.md -Destination $backupDir
```

복사된 파일과 위치를 확인하고 비밀정보가 포함되지 않았는지 검토합니다. 이 계획은 실행 안내이며, 이번 편집에서 실제 백업을 만들거나 Git 명령을 실행한 것은 아닙니다.

### 복원 순서

1. 원래 작업 폴더를 삭제·초기화하지 말고 그대로 보존합니다.
2. 새 폴더에 공개 저장소를 복제해 제공 파일을 준비합니다.
3. 복원 대상이 더 최신 파일을 덮지 않도록 새 복제본의 세 학생 파일과 백업 파일을 비교합니다.
4. 필요한 경우 `student/extension.mjs`를 먼저 복원하고, 그다음 `docs/STUDENT_GUIDE.md`, `docs/NEW_ENVIRONMENT_RUN_LOG.md`를 각각 같은 경로에 복원합니다. 복사 전후 파일 내용을 확인합니다.
5. 앱 폴더에서 `npm run check`를 실행합니다. 직접 실행 결과를 보지 않았다면 복원 성공으로 기록하지 않습니다.
6. 비밀 설정은 백업에서 복사하지 않습니다. 필요한 경우 담당자의 안전한 절차로 재발급받습니다.

### 복구 불가 범위

파일 백업만으로 만료된 로그인·승인 세션과 일회용 확인 번호, 만료·회수된 승인 및 조치 티켓, 서버에서 사라진 처리 중 요청, 브라우저 메모리의 임시 화면 상태를 되살릴 수 없습니다. 외부 서버의 기록, 계정 권한, 조치 집행 결과도 복원되지 않습니다. 해당 자료는 원천 서비스 또는 담당자의 별도 절차로 다시 확인해야 합니다.

## 6. 버전 차이

- **Node.js:** `package.json`의 `engines.node`는 `24.19.0`입니다. 실행 도구·안내 문서에는 Node.js 22~24 지원 범위가 안내됩니다. 기록의 `v24.20.0`은 22~24 범위에는 들어가지만 정확한 `24.19.0`은 아닙니다. 따라서 `package.json`의 고정 버전으로 실행을 확인했다고 말하지 않습니다.
- **스타터:** `docs/FINAL_PRODUCT_GUIDE.md`는 기준 명세 버전을 `starter 0.2.9`로 표시하고, 현재 `package.json`의 프로젝트 버전은 `0.2.11`입니다. 버전이 다르며, 0.2.11이 0.2.9 기준 명세를 완전히 충족하는지는 별도 검증하지 않았습니다.
- **수정 시점 검증:** 이번 편집에서 앱, 브라우저, 실서버, Git, 포털을 확인하지 않았으며 새 테스트 결과를 추가하지 않았습니다.

문서에는 비밀번호·개인키·토큰 또는 다른 비밀값을 기록하지 않았습니다.
